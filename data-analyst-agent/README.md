# Data Analyst Agent

An agent that answers natural-language questions about **any tabular dataset** (CSV/Excel) by calling analysis tools
on the real data, and that keeps a small, curated **persistent memory** across sessions.

## Setup
```bash
git clone <your-repo-url> && cd data-analyst-agent
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                   # then put your Groq API key in .env
streamlit run app.py
```
Then upload a CSV/Excel file, or click **Use sample dataset** (`sample_data/customers.csv`, generated by
`scripts/make_sample_data.py`). Run the tests with `python -m pytest -q tests` (no API key needed).

## What it uses
- LLM: Groq API, model `openai/gpt-oss-20b` (set `MODEL_NAME` in `.env`), via function/tool calling.
- pandas, scipy, matplotlib for the analysis; SQLite for memory; Streamlit for the UI.
- Optional: `sentence-transformers` (`all-MiniLM-L6-v2`) for semantic memory recall (`USE_EMBEDDINGS=true`).

## Tools (`analyst/tools.py`)
| Tool | What it does |
|---|---|
| `profile_dataset` | Rows, column types, missing values, ranges, top categories, duplicates |
| `query_data` | Filter, group and aggregate (pivot-style exact numbers) |
| `correlation` | Strongest numeric relationships with p-values (Pearson/Spearman) |
| `statistical_test` | Welch t-test, ANOVA (+ Kruskal-Wallis) or chi-square, with effect sizes |
| `detect_outliers` | IQR or z-score outliers with the most extreme rows |
| `trend_analysis` | Per-period aggregate (day to year) plus linear trend, change %, best/worst period |
| `make_chart` | Bar, line, histogram, scatter, box plot saved as PNG |
| `remember` / `forget` / `list_memories` | Memory tools the agent calls itself |

Tools take column names as arguments and read the schema from whatever table is loaded, so nothing is tied to one dataset.
Row filters use `pandas.query` syntax and are validated (no `__`, `@`, imports, `open`, etc.).
Tool errors are returned to the model so it can correct its call.

## Memory design (`analyst/memory.py`)
Not a chat log. Only durable things are saved, as four kinds: **definition**, **correction**, **preference**, **filter**.
- The agent decides what is worth keeping (instructions in `analyst/agent.py`); one-off questions are not saved.
- One active entry per name. A changed value **supersedes** the old one (old one kept as history); an identical repeat is ignored.
  A correction replaces the definition it fixes.
- Retrieval: preferences always apply; definitions/filters are injected only when relevant to the question.
- A saved **filter** is real: `query_data` etc. accept `filter_name` and apply the stored query.
- Scope: preferences are global; the rest belong to a dataset id (a hash of the column names, so the same schema
  re-uploaded keeps its memory).
- Stored in SQLite (`data/memory.sqlite`), so it survives restarts. The sidebar lists everything remembered and
  lets the user delete entries.

## Tests
`tests/test_all.py` covers every tool (checked against plain pandas), a second dataset, filter validation, memory
rules and persistence, and the agent loop with a scripted fake LLM, including "memory saved in session 1 changes the
answer in session 2".

## Limitations
- The live Groq tool-calling path has to be tried with your own API key; tests use a scripted fake model.
- Memory recall is keyword-based unless embeddings are enabled.
- Very large files are loaded fully into memory.
